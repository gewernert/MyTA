# MyTA Experiment Instructions

## Scope

These instructions apply to all work inside `experiments/`.

## Operating rules

1. Work only on the `website-redesign` branch.
2. Preserve existing work. Never reset, clean, stash, delete, or overwrite unrelated files.
3. Keep production, deployment, dependencies, and product application files untouched unless the task explicitly authorizes them.
4. Use approved MyTA copy and real product evidence only.
5. Never invent interfaces, metrics, customers, integrations, certifications, outcomes, or testimonials.
6. Read `design/WEBSITE_ART_DIRECTION_LOCK.md` and `design/WEBSITE_VISUAL_QA.md` before any marketing website task.
7. Treat approved desktop and mobile screenshots as the visual source of truth.
8. Use one reference role per section. Do not blend multiple visual brands.
9. Avoid generic AI website patterns, including feature card grids, gradient text, glowing graphics, fake dashboards, floating labels, excessive pills, abstract AI imagery, and empty space used as decoration.
10. Keep each task narrow. Do not add sections, features, copy, or motion outside the requested scope.
11. Use real browser captures at the requested viewports.
12. Never use Codex self assessment as proof. Provide rendered evidence.
13. Perform no more than the correction passes explicitly allowed by the task.
14. Stop at the stated stop condition.
15. Report remaining differences honestly.

## Standard evidence viewports

1. Desktop: 1440 by 1000
2. Tablet: 1024 by 768
3. Mobile: 390 by 844

## Quality standard

The page should feel authored through hierarchy, proportion, typography, product truth, responsive composition, and restraint. Do not attempt to create quality through decoration.
