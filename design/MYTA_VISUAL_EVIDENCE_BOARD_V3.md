# MyTA Visual Evidence Board v3

**Status:** Final capture specification before the MyTA Design Contract

## Purpose

This board defines the external evidence used to create MyTA visual concepts. It is not a mood board and does not authorize copying another company’s brand.

The final MyTA concept must express:

> The instructor sets the context. The student does the thinking. Useful learning signals return to the instructor.

## Rules

1. Capture all 12 references at desktop and mobile widths.
2. Record detailed measurements for construction references and only essential hierarchy measurements for market or competitive references.
3. Construction references guide hierarchy and product presentation.
4. Education references guide customer language and workflow framing.
5. Competitive references define what MyTA must not become.
6. External screenshots are internal research artifacts. Never deploy, publish, or import them into the production site.
7. The approved MyTA target, not the reference site, controls Codex implementation.
8. Human review is required before the Design Contract begins.

## Required measurements

For references 01 through 06, record detailed measurements when technically available:

1. Viewport size.
2. Main content width.
3. Main heading font size, line height, width, and line count.
4. Supporting body font size, line height, and width.
5. Product visual width as a percentage of the main composition.
6. Approximate top and bottom spacing of the captured section.
7. Primary radius and border treatment.
8. Whether the layout is centered, split, asymmetrical, sticky, tabbed, or stacked.
9. How the mobile composition differs from desktop.
10. Any meaningful motion or scroll behavior.

For references 07 through 12, record only layout type, information hierarchy, product evidence, CTA structure, mobile rearrangement, and the relevant category convention or anti-pattern. These references are not CSS templates.

## Approval gate

The evidence board is not approved until a human reviewer confirms:

1. Every capture shows the intended current section.
2. Both desktop and mobile behavior are represented.
3. Measurements are complete enough to inform the Design Contract.
4. No screenshots are deployed or committed into a public web root.
5. Each reference has a clear borrow and reject role.
6. Competitive references are not treated as visual models.
7. The set supports MyTA’s vision without turning the homepage into an objection page.
8. The next phase remains concept design, not production implementation.
