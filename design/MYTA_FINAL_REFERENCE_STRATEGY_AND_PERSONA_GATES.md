# MyTA Final Reference Strategy and Persona Approval Gates

**Status:** Final research gate before visual concept development  
**Version:** July 2026  
**Purpose:** Select the exact reference set for MyTA, define how each reference may be used, and establish independent persona gates that every proposed design must pass before Codex implementation.

---

## 1. Executive decision

The earlier reference pack was directionally useful, but it was not rigorous enough.

It repeated some brands too often, mixed visual inspiration with product messaging, and did not clearly distinguish between:

1. References MyTA should borrow from.
2. Competitors MyTA must understand.
3. Patterns MyTA should deliberately reject.

The final system now uses three layers:

### Layer A: Construction references

These provide proven patterns for composition, hierarchy, workflow explanation, product presentation, and conversion.

### Layer B: Customer and market references

These provide educator language, product framing, and adoption language relevant to MyTA’s audience.

### Layer C: Competitive boundary references

These prevent MyTA from copying the category average or making claims that competitors already make.

No single website is the design model.

The final MyTA design must synthesize the relevant principles around MyTA’s own point of view:

> The instructor sets the context. The student does the thinking. Useful learning signals return to the instructor.

---

## 2. Research conclusions that control the process

### 2.1 The website must explain the immediate customer value

Early-stage B2B websites must speak to a narrow audience and immediate problem rather than copying a pitch deck or the abstract language of a scaled company.

MyTA application:

1. Lead with the assignment problem.
2. Explain what the instructor can do.
3. Show what the student experiences.
4. Show what returns to the instructor.
5. Make one course the next step.

### 2.2 “AI-powered” is not a distinctive position

AI products become interchangeable when they use the same gradients, sterile screenshots, broad claims, and enterprise-ready language.

MyTA’s difference must be visible in:

1. The assignment-centered story.
2. Instructor-defined context and support rules.
3. Active student thinking.
4. Learning signals connected to instructor action.
5. A recognizable visual identity that is not generic AI styling.

### 2.3 The real product must carry the story

B2B software buyers seek real interface imagery. Abstract representations are not enough.

MyTA must use:

1. Instructor assignment setup.
2. Student assignment with guided AI support.
3. Instructor analytics and learning signals.

These should be large, readable, and distributed through the page.

### 2.4 Design must be resolved before code

Generated output is not the same as design. Design requires understanding the context and resolving competing forces before implementation.

Codex should implement an approved target. It should not invent and approve the art direction.

### 2.5 The whole page is designed together, then implemented in bounded tasks

The complete desktop and mobile concept must be resolved first so section rhythm and brand expression remain coherent.

Codex then implements one major section at a time against the approved target.

### 2.6 The homepage should express the vision, not answer every objection

Faculty concerns should shape:

1. Claims.
2. Tone.
3. Product proof.
4. Trust.
5. The Pilot framing.

They should not turn the homepage into a defensive FAQ.

### 2.7 Institutional review belongs after product value

Privacy, accessibility, security, permissions, and data boundaries matter. They should appear as a contained layer after the visitor understands the product.

### 2.8 Plain language and mobile are primary requirements

The site should use short sentences, familiar words, clear headings, and a mobile composition designed independently rather than stacked mechanically.

## 5. Persona approval reviews

The reference strategy and future design must pass every persona gate below.

A design that fails any gate returns to concept development. Codex implementation does not begin.

---

# Persona 1: University instructor

## Mindset

“I am deciding whether this is relevant to one of my courses and whether it will preserve the thinking I expect students to do.”

## What this persona wants

1. A recognizable assignment problem.
2. Clear instructor authority.
3. Evidence that students still do the work.
4. A useful outcome, not another dashboard.
5. A manageable first step.
6. A product that does not insult their teaching or assume every course is the same.

## What causes rejection

1. Generic “AI will transform education” language.
2. A chatbot with no assignment context.
3. Claims that every instructor needs process monitoring.
4. Surveillance or policing language.
5. A vague enterprise platform.
6. A pilot that sounds like extra institutional work before value is visible.

## Reference-set review

**Pass**

The set includes direct assignment framing, instructor control, guided student work, real interfaces, and course-level adoption.

The design must preserve vision and confidence rather than becoming a page of objections.

## Required design evidence

1. Instructor setup appears in the product story.
2. Student responsibility is clear.
3. The instructor can describe what returns to them.
4. The Pilot begins with one assignment or course.

## 9. Next gate

The next phase is not Codex implementation.

The next phase is:

1. Capture the 12 exact sections.
2. Create a visual evidence board with the borrow and reject notes beside each screenshot.
3. Build the MyTA Design Contract from the evidence.
4. Produce three complete desktop and mobile concepts.
5. Run every concept through all eight persona reviews.
6. Reject any concept that fails one gate.
7. Select and refine one final target.
8. Only then begin section-by-section Codex implementation.

---

## 10. Final rule

Research does not mechanically produce one perfect visual design.

Research defines the problem, the audience, the constraints, the successful patterns, and the failure conditions.

Human approval selects the final expression.

Codex implements that approved expression.

No agent is allowed to invent, implement, and approve the same design.
